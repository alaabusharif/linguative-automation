## English copy

### How to Brief a Translation Provider for an Institutional Report

**Meta description:** A practical brief for translating institutional reports: define audiences, files, terminology, review roles, confidentiality, formats and sign-off.

**Summary:** A useful translation brief does more than name the language pair. It identifies the intended reader, the approved source files, the references that govern terminology, the required deliverables and the people authorised to answer questions and approve the final text.

For an institutional report, send one controlled source package and a short written brief covering purpose, audience, language direction, terminology, file formats, confidentiality, review roles and deadline. Agree how queries and source changes will be handled before translation begins. This reduces ambiguity without pretending that every revision can be absorbed inside the original schedule.

### What should an institutional translation brief contain?

At minimum, state what the report is for, who will read it, which source version is approved, the source and target languages, the required files, the review route and the date each deliverable is needed. Add the terminology and reference material that should guide the work, and identify one person who can resolve questions.

Language direction alone is not enough. An English version for an international board may need different explanations from an English version intended for a specialist donor team. Likewise, an Arabic report for publication may require approved institutional names and public-facing wording, while an internal working translation may prioritise speed and an editable format. Describe the decision the reader should be able to make after reading the translated report.

If a procurement form asks only for page count and language pair, attach a content brief. Price and timing depend on more than pages: editable text, scanned annexes, tables, graphics, specialist terminology, layout and review expectations can all change the work required. Ask the provider to state assumptions and exclusions in the proposal.

- Purpose, audience and intended use of the translated report.
- Source language, target language and any required regional or institutional conventions.
- Approved source version, file inventory and materials still expected.
- Deliverables, review roles, query contact and milestone dates.

### Freeze the source package and map every file

Create one source folder and an inventory that lists the main report, annexes, tables, captions and linked material. Mark the file that controls the text and remove obsolete versions from the active folder. If the report is still being edited, label it clearly and agree a cut-off or change-control process rather than allowing silent replacements.

Provide editable source files where they exist. A PDF is useful for showing the intended appearance, but it may not expose text in charts, diagrams or scanned pages. If numbers in a chart must be recreated or translated text must be placed back into artwork, say so. Do not assume that translation of the report body automatically includes rebuilding every graphic.

Use a simple version label and send a change note for each replacement: which file changed, which passages changed and whether previous translation work should be updated. A shared folder can distribute files, but it does not by itself establish which version is approved.

### Supply terminology, names and reference decisions

Give the provider material that answers real language questions: an approved glossary, previous final reports, official names of programmes and institutions, acronyms, style guidance and links to authoritative public references. Identify which references are binding and which are examples. A large archive without priorities can create more uncertainty than a short, curated pack.

Flag terms that must remain in the source language, names that have an official Arabic or English form and expressions that are still awaiting a decision. When two earlier reports use different wording, choose the preferred form or authorise the reviewer to decide. Do not present automatically extracted terminology as approved unless a responsible person has checked it.

Clear, consistent source writing also matters. Resolve obvious contradictions, unexplained abbreviations and incomplete captions before handover where possible. If they must remain, tell the provider whether to query them, reproduce them faithfully or add an agreed editorial note.

### Define deliverables, confidentiality and access

List each output separately. Examples include an editable translated document, a laid-out PDF, translated tables, a bilingual terminology list or a web-ready excerpt. Specify whether hyperlinks, footnotes, references, headers, alt text and document properties are within scope. If publication layout is required, provide the template, fonts and brand rules that the provider is authorised to use.

For restricted reports, agree who may receive the files, how access will be granted and any return, retention or deletion requirement. Give the translation team access to the references it is expected to follow; a protected link that the assigned team cannot open is not a usable reference. Do not include personal or confidential material that is unnecessary for the assignment.

Ask how translation, editing, proofreading and formatting are separated in the proposed workflow. ISO 17100 describes requirements for core translation processes and resources, but referencing the standard is not evidence that a provider is certified to it. If certification is a procurement requirement, request current, verifiable evidence rather than assuming it from general quality language.

### Build one review and approval route

Name a subject reviewer for factual and technical questions, a language reviewer for terminology and style where needed, and one person authorised to approve the final version. In a small team, one person may hold more than one role; the important point is that the provider knows whose decision controls when comments conflict.

Collect internal comments into one marked file or agreed review system. Distinguish corrections from preferences and explain changes to recurring terminology so they can be applied consistently. Parallel reviewers returning separate documents can create contradictory edits and conceal which version is final.

Plan time for translation, provider review, client review, query resolution, layout and final proof. A source change after translation begins may affect both cost and delivery. Agree how the provider will assess the effect before accepting the change, especially when it alters figures, conclusions or repeated terminology.

- One channel for translation queries and one owner for source changes.
- A consolidated review file with an agreed return date.
- A named final approver for each language version.
- A final comparison of text, tables, captions and layout before release.

### Worked example: a bilingual annual report

This is a hypothetical planning example, not a Linguative client project. An institution needs an Arabic annual report translated into English for international partners. The package contains a 60-page editable document, an approved PDF, three Excel tables and six charts whose labels are embedded in design files. An executive summary will also be published online.

The brief identifies the approved Arabic file and the cut-off date for source edits. It requests an edited English document, updated chart labels supplied as a separate table, a laid-out English PDF and a web-ready executive summary. It includes approved English names, the previous year's final report and a short glossary. One programme specialist answers factual queries; the communications lead consolidates comments and approves the final English wording.

The provider can now quote against visible assumptions: the charts require translation but not artwork editing unless added, the tables must be checked against the source, and the web summary is a separate deliverable. If the institution later replaces the financial section, both sides have a route to identify the affected text and revise timing before work continues.

Linguative provides institutional translation with editing, proofreading and formatting where agreed. A proposal should still describe the exact documents, review steps and deliverables for this assignment; the value of one accountable language team depends on a clear written scope.

### Before requesting a translation proposal

- State the report's purpose, audience, intended use and language direction.
- Identify the approved source version and list every file, annex, table and graphic.
- Provide editable files plus a reference PDF where available.
- Share approved names, terminology, previous final translations and style guidance.
- List each deliverable and say whether layout, charts and web excerpts are included.
- Define confidentiality, file access and any retention or deletion requirements.
- Name the query contact, reviewers and final approver; consolidate comments.
- Set milestones for translation, review, layout, proof and final sign-off.
- Ask the provider to record assumptions, exclusions and the effect of source changes.

### FAQ

**Is a PDF enough to request a translation quote?**

It can support an initial estimate, but provide editable files and an inventory where possible. Scanned pages, embedded chart text, layout work and inaccessible annexes may affect scope, price and timing.

**Should we send previous translations?**

Yes, if they are approved and relevant. Label the version and explain whether its terminology is mandatory or only a reference. Do not ask the provider to infer approval from a folder of conflicting files.

**Who should review the translated report?**

Use people who understand the subject and the target-language audience, then appoint one final approver. Consolidate comments before returning them so the provider is not asked to reconcile unexplained conflicts.

**What happens if the source report changes during translation?**

Send a controlled replacement and a change note. Ask the provider to identify the affected work and confirm any timing or cost effect before treating the revision as part of the original scope.

## النص العربي

### كيف تُعدّ طلبًا واضحًا لترجمة تقرير مؤسسي؟

**Meta description:** دليل عملي لإعداد طلب ترجمة التقارير المؤسسية: الجمهور والملفات والمصطلحات والمراجعة والسرية والتنسيق والاعتماد النهائي.

**Summary:** لا يقتصر طلب الترجمة الجيد على تحديد اللغتين. بل يوضح القارئ المستهدف، ونسخة المصدر المعتمدة، والمراجع الحاكمة للمصطلحات، والمخرجات المطلوبة، ومن يجيب عن الاستفسارات ومن يعتمد النص النهائي.

عند ترجمة تقرير مؤسسي، أرسل حزمة مصدر واحدة ومنضبطة، وأرفق بها طلبًا مكتوبًا يحدد الغرض والجمهور واتجاه الترجمة والمصطلحات وصيغ الملفات والسرية وأدوار المراجعة والمواعيد. واتفق قبل بدء العمل على طريقة معالجة الاستفسارات وتعديلات المصدر؛ فهذا يقلل الالتباس من دون افتراض أن كل تعديل يمكن استيعابه ضمن الجدول الأصلي.

### ما الذي ينبغي أن يتضمنه طلب ترجمة تقرير مؤسسي؟

حدّد على الأقل غرض التقرير، ومن سيقرأه، ونسخة المصدر المعتمدة، ولغة المصدر واللغة المطلوبة، والملفات التي يجب تسليمها، ومسار المراجعة، وموعد كل مخرج. وأضف المصطلحات والمراجع التي ينبغي الرجوع إليها، وسمِّ شخصًا واحدًا مخولًا بحسم الاستفسارات.

لا يكفي ذكر اتجاه الترجمة. فالنسخة الإنجليزية الموجهة إلى مجلس دولي قد تحتاج إلى شروح تختلف عن نسخة مخصصة لجهة مانحة متخصصة. وكذلك قد تتطلب النسخة العربية المعدّة للنشر أسماء مؤسسية معتمدة وصياغة مناسبة للجمهور، بينما تركز ترجمة عمل داخلية على السرعة وتسليم ملف قابل للتحرير. اشرح القرار أو الفهم الذي يفترض أن يصل إليه القارئ بعد الاطلاع على التقرير المترجم.

إذا كان نموذج المشتريات يطلب عدد الصفحات واللغتين فقط، فأرفق به موجزًا للمحتوى. لا يتحدد السعر والمدة بعدد الصفحات وحده؛ إذ قد تؤثر الملفات القابلة للتحرير والملاحق الممسوحة والجداول والرسومات والمصطلحات المتخصصة والتنسيق ومتطلبات المراجعة في حجم العمل. اطلب من مزود الخدمة أن يوضح افتراضاته وما لا يشمله عرضه.

- غرض التقرير وجمهوره والاستخدام المقصود من النسخة المترجمة.
- لغة المصدر واللغة المطلوبة وأي أعراف إقليمية أو مؤسسية واجبة الاتباع.
- نسخة المصدر المعتمدة وقائمة الملفات والمواد التي لم تصل بعد.
- المخرجات وأدوار المراجعة ومسؤول الاستفسارات والمواعيد المرحلية.

### ثبّت حزمة المصدر وأعدّ قائمة دقيقة بالملفات

أنشئ مجلدًا واحدًا للمصدر، وأرفق به قائمة تشمل التقرير الرئيس والملاحق والجداول والتعليقات التوضيحية والمواد المرتبطة. حدّد الملف المرجعي للنص، وأبعد النسخ القديمة عن المجلد النشط. وإذا كان التقرير ما يزال قيد التحرير، فوضّح ذلك واتفق على موعد لإقفال النص أو آلية لضبط التعديلات بدل استبدال الملفات من دون إشعار.

قدّم الملفات الأصلية القابلة للتحرير متى توفرت. يفيد ملف PDF في إظهار الشكل المقصود، لكنه قد لا يتيح نصوص الرسومات والمخططات أو الصفحات الممسوحة. وإذا كانت أرقام الرسم ستُعاد صياغتها أو كان المطلوب إدراج النص المترجم في ملفات التصميم، فاذكر ذلك صراحة. لا تفترض أن ترجمة متن التقرير تشمل تلقائيًا إعادة بناء كل رسم.

استخدم تسمية بسيطة للإصدارات، وأرسل مع كل بديل ملاحظة توضح الملف الذي تغير، والمواضع المتأثرة، وما إذا كان ينبغي تحديث ما سبق ترجمته. يسهّل المجلد المشترك توزيع الملفات، لكنه لا يثبت وحده أي نسخة هي المعتمدة.

### قدّم المصطلحات والأسماء والقرارات المرجعية

زوّد فريق الترجمة بمواد تجيب عن الأسئلة اللغوية الفعلية: مسرد معتمد، وتقارير نهائية سابقة، والأسماء الرسمية للبرامج والمؤسسات، والاختصارات، ودليل الأسلوب، وروابط إلى مراجع عامة موثوقة. وبيّن ما هو ملزم وما يقدَّم للاستئناس فقط؛ فقد يسبب أرشيف كبير بلا أولويات حيرة أكبر من حزمة قصيرة منتقاة بعناية.

حدّد المصطلحات التي يجب إبقاؤها بلغة المصدر، والأسماء ذات الصيغة العربية أو الإنجليزية الرسمية، والتعبيرات التي لم يُحسم مقابلها بعد. وإذا استخدمت تقارير سابقة صيغتين مختلفتين، فاختر الصيغة المفضلة أو فوّض المراجع باتخاذ القرار. ولا تصف قائمة مستخرجة آليًا بأنها معتمدة ما لم يراجعها مسؤول مختص.

تساعد سلامة نص المصدر واتساقه كذلك. عالج التناقضات الظاهرة والاختصارات غير المفسرة والتعليقات الناقصة قبل التسليم متى أمكن. وإذا تعذر ذلك، فحدد هل ينبغي لفريق الترجمة الاستفسار عنها، أم نقلها كما هي، أم إضافة ملاحظة تحريرية متفق عليها.

### حدّد المخرجات والسرية وصلاحيات الوصول

اكتب كل مخرج على حدة؛ مثل ملف مترجم قابل للتحرير، أو ملف PDF منسق، أو جداول مترجمة، أو قائمة مصطلحات ثنائية اللغة، أو مقتطف جاهز للنشر على الموقع. ووضّح ما إذا كانت الروابط والحواشي والمراجع والرؤوس والنصوص البديلة وخصائص المستند ضمن النطاق. وإذا كان المطلوب تنسيقًا للنشر، فأرسل القالب والخطوط وقواعد الهوية المصرح باستخدامها.

في التقارير المقيدة، اتفق على الأشخاص المصرح لهم باستلام الملفات، وطريقة منح الوصول، وأي متطلبات لإعادة الملفات أو الاحتفاظ بها أو حذفها. وأتح لفريق الترجمة الوصول إلى المراجع التي يُطلب منه اتباعها؛ فالرابط المحمي الذي لا يستطيع الفريق فتحه ليس مرجعًا قابلًا للاستخدام. ولا ترسل بيانات شخصية أو سرية لا يحتاجها العمل.

اسأل عن الفصل بين الترجمة والتحرير والتدقيق والتنسيق في سير العمل المقترح. يصف معيار ISO 17100 متطلبات للعمليات والموارد الأساسية في خدمات الترجمة، لكن الإشارة إليه لا تثبت أن مزود الخدمة حاصل على شهادة مطابقة. وإذا كانت الشهادة شرطًا للمشتريات، فاطلب دليلًا حاليًا يمكن التحقق منه بدل استنتاجها من عبارات عامة عن الجودة.

### أنشئ مسارًا واحدًا للمراجعة والاعتماد

سمِّ مراجعًا متخصصًا للأسئلة الموضوعية والفنية، ومراجعًا لغويًا للمصطلحات والأسلوب عند الحاجة، وشخصًا واحدًا مخولًا باعتماد النسخة النهائية. قد يجمع شخص واحد أكثر من دور في فريق صغير؛ المهم أن يعرف مزود الخدمة رأي من يُعتمد عند تعارض الملاحظات.

اجمع التعليقات الداخلية في ملف واحد موضح أو في نظام مراجعة متفق عليه. ميّز التصحيحات من التفضيلات، واشرح التعديل على المصطلحات المتكررة حتى يطبَّق باتساق. أما إرسال ملفات منفصلة من مراجعين متعددين فقد ينتج تعديلات متعارضة ويخفي النسخة النهائية.

خصّص وقتًا للترجمة ومراجعة المزود ومراجعة الجهة وحسم الاستفسارات والتنسيق والتدقيق النهائي. وقد يؤدي تعديل المصدر بعد بدء العمل إلى تغيير التكلفة والموعد. اتفق على طريقة تقييم أثر التعديل قبل قبوله، ولا سيما إذا مسّ الأرقام أو الاستنتاجات أو مصطلحات تتكرر في التقرير.

- قناة واحدة لاستفسارات الترجمة ومسؤول واحد عن تعديلات المصدر.
- ملف موحد للمراجعة وموعد متفق عليه لإعادته.
- معتمد نهائي مسمى لكل نسخة لغوية.
- مقارنة نهائية للنص والجداول والتعليقات والتنسيق قبل النشر.

### مثال تطبيقي: تقرير سنوي ثنائي اللغة

هذا مثال افتراضي للتخطيط، وليس عرضًا لمشروع نفذته شركة الإبداع اللغوي. تحتاج مؤسسة إلى ترجمة تقرير سنوي من العربية إلى الإنجليزية لشركائها الدوليين. تشمل الحزمة مستندًا قابلًا للتحرير من 60 صفحة، وملف PDF معتمدًا، وثلاثة جداول Excel، وستة مخططات أُدرجت عناوينها داخل ملفات التصميم. كما سيُنشر الملخص التنفيذي على الموقع.

يحدد الطلب ملف العربية المعتمد وموعد إقفال التعديلات. ويطلب مستندًا إنجليزيًا محررًا، وترجمة عناوين المخططات في جدول منفصل، وملف PDF إنجليزيًا منسقًا، وملخصًا تنفيذيًا جاهزًا للموقع. ويرفق الأسماء الإنجليزية المعتمدة، والتقرير النهائي للسنة السابقة، ومسردًا مختصرًا. يجيب متخصص في البرامج عن الأسئلة الفنية، بينما تجمع مسؤولة الاتصال التعليقات وتعتمد الصياغة الإنجليزية النهائية.

يستطيع مزود الخدمة الآن إعداد عرض قائم على افتراضات ظاهرة: تُترجم نصوص المخططات، لكن تعديل ملفات التصميم لا يدخل ضمن النطاق ما لم يُضف؛ وتُراجع الجداول مقابل المصدر؛ ويُعامل ملخص الموقع كمخرج مستقل. وإذا استبدلت المؤسسة القسم المالي لاحقًا، فهناك مسار لتحديد النص المتأثر ومراجعة الموعد قبل استكمال العمل.

تقدم شركة الإبداع اللغوي ترجمة مؤسسية مع التحرير والتدقيق والتنسيق بحسب النطاق المتفق عليه. ومع ذلك، ينبغي أن يصف كل عرض بدقة مستندات هذه المهمة وخطوات مراجعتها ومخرجاتها؛ فجدوى فريق لغوي واحد مسؤول تعتمد على وضوح النطاق المكتوب.

### قبل طلب عرض الترجمة

- حدّد غرض التقرير وجمهوره واستخدامه المقصود واتجاه الترجمة.
- عيّن نسخة المصدر المعتمدة وأدرج جميع الملفات والملاحق والجداول والرسومات.
- قدّم الملفات القابلة للتحرير مع ملف PDF مرجعي إن توفر.
- شارك الأسماء والمصطلحات المعتمدة والترجمات النهائية السابقة ودليل الأسلوب.
- اكتب كل مخرج، وبيّن هل يشمل النطاق التنسيق والمخططات ومقتطفات الموقع.
- حدّد السرية وصلاحيات الوصول وأي متطلبات للاحتفاظ بالملفات أو حذفها.
- سمِّ مسؤول الاستفسارات والمراجعين والمعتمد النهائي، واجمع التعليقات.
- ضع مواعيد للترجمة والمراجعة والتنسيق والتدقيق والاعتماد النهائي.
- اطلب من المزود توثيق الافتراضات والاستثناءات وأثر تعديلات المصدر.

### FAQ

**هل يكفي ملف PDF لطلب عرض ترجمة؟**

يمكن أن يساعد في إعداد تقدير أولي، لكن قدّم الملفات القابلة للتحرير وقائمة بالمحتويات متى أمكن. فالصفحات الممسوحة ونصوص المخططات والتنسيق والملاحق غير المتاحة قد تؤثر في النطاق والسعر والموعد.

**هل نرسل ترجمات السنوات السابقة؟**

نعم، إذا كانت معتمدة وذات صلة. وضّح رقم النسخة، وهل مصطلحاتها ملزمة أم مرجعية فقط. ولا تطلب من المزود استنتاج المعتمد من مجلد يضم ملفات متعارضة.

**من ينبغي أن يراجع التقرير المترجم؟**

اختر أشخاصًا يعرفون الموضوع وجمهور اللغة المستهدفة، ثم سمِّ معتمدًا نهائيًا واحدًا. واجمع التعليقات قبل إعادتها حتى لا يُطلب من المزود التوفيق بين ملاحظات متعارضة بلا تفسير.

**ماذا لو تغير التقرير الأصلي أثناء الترجمة؟**

أرسل بديلًا مضبوطًا مع ملاحظة بالتغييرات. واطلب من المزود تحديد العمل المتأثر وتأكيد أي تغيير في الموعد أو التكلفة قبل اعتبار التعديل جزءًا من النطاق الأصلي.
