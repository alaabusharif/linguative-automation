# Client Reference Policy

This repository is public. It must not be the master storage location for private client names, contacts, rates, project details, or permission records.

Linguative uses a private Client Reference Register as the source of truth for whether a client/reference may be named in a proposal, public case study, website, social post, capability statement, testimonial, logo wall, or other material.

## Usage classes

- PUBLIC_NAMED — may be named in public marketing/case studies, subject to evidence and any separate logo/testimonial restrictions.
- PROPOSAL_NAMED — may be named in private proposals/credentials; not public marketing.
- ANONYMISED_ONLY — may be described publicly without naming the organization.
- PRIVATE_ONLY — internal use only.
- PENDING — do not name externally until approved.
- PROSPECT_ONLY — never present as a client/reference.

## Rules

1. Never infer permission merely because an engagement occurred.
2. Before using a named reference, verify both the engagement evidence and the usage class in the private register.
3. Public repo files should use reference IDs, generic sector descriptions, and public-safe rules instead of unnecessary client names.
4. Public naming permission does not automatically authorize logos, testimonials, pricing, participant names, confidential documents, or detailed outcomes.
5. Proposal workflows may use only PUBLIC_NAMED or PROPOSAL_NAMED references.
6. Public case studies may use PUBLIC_NAMED, or ANONYMISED_ONLY with identity removed.
7. PENDING, PRIVATE_ONLY, and PROSPECT_ONLY may not be used as named external credentials.
8. Context-specific exceptions are allowed only when the private register says so; for example, a client may be named in a private communication addressed directly to that client while remaining prohibited in public or third-party use.

The private register governs if this public file and a lower-level prompt differ.
